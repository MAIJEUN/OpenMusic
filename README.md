# OpenMusic

YouTube Music 재생목록 링크를 붙여넣으면 **YouTube Music과 같은 화면과 사용감**으로 재생할 수 있는 웹 플레이어입니다.

- 재생은 YouTube 공식 임베드 플레이어(IFrame Player API)로 합니다.
- 재생목록·앨범·가사 같은 메타데이터는 [youtubei.js](https://github.com/LuanRT/YouTube.js)로 가져옵니다.
- 로그인 없이 쓰며, 등록한 재생목록·내 재생목록·좋아요는 브라우저(localStorage)에 저장됩니다.

## 주요 기능

| 영역 | 기능 |
|---|---|
| 링크 열기 | `music.youtube.com/playlist?list=…`, `/browse/MPRE…`(앨범), `/watch?v=…&list=…`, `youtube.com`·`youtu.be` 재생목록 링크. 상단 입력칸에 붙여넣으면 바로 열립니다. 주소의 `music.youtube.com` 부분만 이 사이트 주소로 바꿔도 같은 페이지가 열립니다. |
| Spotify · SoundCloud | **Spotify**: 재생목록·앨범·곡 링크(`open.spotify.com/…`, `spotify:playlist:…`, `spotify.link` 짧은 주소)를 열 수 있습니다. Spotify는 외부 사이트에서 전체 곡을 틀 수 없어서, 곡을 재생할 때 YouTube Music에서 같은 곡(제목·가수·길이 비교)을 찾아 대신 틉니다. 다음 두 곡은 미리 찾아 두고, 못 찾은 곡은 알림 후 건너뜁니다. 로그인 없이 볼 수 있는 임베드 페이지를 읽기 때문에 재생목록은 **앞 100곡까지만** 불러오며, Spotify 카탈로그 검색은 API 키가 필요해 지원하지 않습니다. **SoundCloud**: 검색(검색 결과의 **SoundCloud** 칩)과 곡·재생목록(sets)·아티스트 링크(`soundcloud.com/…`, `on.soundcloud.com/…`)를 지원하며, SoundCloud 공식 임베드 플레이어로 직접 재생합니다(동영상 화면에는 SoundCloud 플레이어가 보입니다). 미리듣기만 허용되거나 임베드가 막힌 곡은 목록에서 빠집니다. |
| 재생목록 등록 | 링크로 연 재생목록·앨범은 사이드바(모바일은 홈)에 자동 등록되어 언제든 다시 불러올 수 있습니다. 읽기 전용이며, ✕ 버튼이나 메뉴로 삭제(실행취소 가능)합니다. **원본 변경 반영**: 등록한 재생목록은 열 때마다 원본을 새로 확인해 곡 추가·삭제·순서 변경을 그대로 보여주고, 그 재생목록을 재생 중이면 대기열에도 반영합니다(재생 중에는 10분마다, 다른 탭·앱에서 돌아왔을 때도 확인). 지금 듣는 곡은 원본에서 빠져도 끝까지 재생되고, 직접 추가한 곡은 그대로 남으며, 셔플 중이면 섞인 순서를 유지한 채 새 곡만 아직 안 들은 쪽에 끼워 넣습니다. |
| 노래 검색 | 상단 입력칸에 검색어를 입력하면 노래/동영상을 검색하고, 링크를 붙여넣으면 바로 엽니다. 검색 결과의 곡을 누르면 그 곡만 단순 재생합니다. |
| 내 재생목록 | 사이트에서 직접 만든 재생목록. 곡 메뉴의 **재생목록에 저장**으로 추가하고, 메뉴로 삭제, 끌어서 순서 변경, 이름 바꾸기, 재생목록 삭제(확인 창 + 실행취소)를 할 수 있습니다. 불러온 재생목록은 **내 재생목록으로 복사**할 수 있습니다. |
| 현재 재생목록 저장 | 플레이어 페이지 **다음 트랙** 위의 **저장** 버튼으로 지금 대기열을 새 재생목록(또는 기존 내 재생목록)에 저장합니다. |
| 좋아요 | 곡 목록·재생 바·플레이어 페이지의 하트를 누르면 사이드바의 **좋아요 표시한 음악**에 모입니다. |
| 재생 | 재생/일시중지, 이전/다음, 탐색(드래그), 볼륨, 반복(사용 안함/모두/한 곡), 재생 불가 곡 자동 건너뛰기 |
| 곡 넘김 (설정 ⚙) | 상단 **설정**에서 켜고 끕니다. **크로스페이드**(0~12초, 기본 5초): 곡 끝 N초 전부터 다음 곡을 두 번째 플레이어로 겹쳐 틀며 볼륨을 엇갈리게 바꿉니다. **노래가 아닌 구간 건너뛰기**: [SponsorBlock](https://sponsor.ajay.app) 공개 데이터(뮤직비디오의 노래 아닌 구간·아웃트로)를 사이트에서 직접 조회해, 중간 구간은 건너뛰고 영상 끝까지 이어지는 구간은 '노래 끝'으로 보고 바로 다음 곡으로(크로스페이드) 넘어갑니다. 영상 ID 해시 앞 4자리로만 조회합니다. **곡 끝 무음 건너뛰기**: 실시간 스펙트럼이 켜져 있을 때 곡 후반부에 정한 시간(1~10초, 기본 3초) 넘게 소리가 없으면 다음 곡으로 넘어갑니다. |
| 셔플 | 켜 두면 다른 재생목록·곡을 골라도 유지됩니다. 켜는 순간 지금 곡이 맨 앞에 오고 나머지 전체가 섞이며, 끄면 원래 순서로 돌아갑니다. 셔플 중 곡을 누르면 그 곡부터, 재생 버튼은 첫 곡부터(그 뒤 곡들만 섞임), 셔플 버튼은 무작위 곡부터 시작합니다. '모두 반복'으로 한 바퀴 돌면 새 순서로 다시 섞습니다. |
| 실시간 스펙트럼 | 재생 바의 스펙트럼 버튼을 누르고 공유 창에서 **이 탭 + 탭 오디오 공유**를 선택하면, 실제 재생 중인 소리를 분석해 재생 바 배경의 은은한 곡선 그래프와 재생 중 표시 막대에 보여줍니다. YouTube 플레이어는 다른 출처(iframe)라 소리를 직접 읽을 수 없어 탭 오디오 캡처를 사용하며, 데스크톱 Chrome·Edge에서 동작합니다. 꺼져 있을 때 막대는 움직이지 않습니다. |
| 테마 색 | 재생 중인 곡의 앨범 아트에서 대표 색 두 가지를 뽑아 페이지 배경 빛, 재생 바, 진행 막대, 스펙트럼 색을 곡에 맞춰 부드럽게 바꿉니다. 플레이어 페이지에서 **동영상**을 보는 중이면 영상 색을 따라갑니다. 실시간 스펙트럼(탭 공유)이 켜져 있으면 실제 화면의 동영상 영역을 0.5초마다 읽고, 꺼져 있으면 YouTube 장면 썸네일(약 25·50·75% 지점)을 재생 위치에 맞춰 사용합니다. (이미지 픽셀을 읽기 위해 `/api/image`가 YouTube/Google 썸네일만 중계합니다.) |
| 플레이어 페이지 | **노래/동영상 전환**: YouTube Music처럼 '노래'는 음원(노래) 버전, '동영상'은 뮤직비디오를 틉니다(같은 제목·가수의 다른 버전을 찾고, 가사 자동 싱크와 같은 인트로 길이 추정값으로 같은 부분부터 이어서 전환). **다음 트랙**(드래그로 순서 변경, 삭제), **가사** |
| 가사 | YouTube Music과 같은 외부 가사 데이터를 보여줍니다. **실시간 가사**(현재 줄 강조, 끝난 줄은 비활성 색으로 부드럽게 전환, 멀수록 흐려지는 앞뒤 줄, 인트로·간주 • • • 표시, 자동 스크롤, 줄을 누르면 그 위치로 이동)를 먼저 찾고 — ⓪ 단어별 시간이 있는 가사(NetEase Cloud Music yrc·비공식 API, LRCLIB Enhanced LRC)면 **노래방처럼 단어마다 차오르는 효과** ① YouTube Music 모바일 앱의 시간 동기화 가사 ② [LRCLIB](https://lrclib.net) 공개 가사 DB(곡 제목·가수·길이로 검색) — 없으면 일반 가사를 보여줍니다. 커버곡처럼 가사를 못 찾으면 제목에서 원곡을 찾아 **원곡 가사**를 보여줍니다(제목·영상 설명란에 적힌 원곡 가수, 꾸밈말 없는 제목, 비슷한 길이 우선, 리믹스·반주 등 다른 버전은 뒤로). 다른 곡 가사가 잡히면 가사 아래 **가사가 맞지 않나요?**에서 다른 원곡 후보를 고르거나 그 영상에서만 가사를 숨길 수 있습니다(영상별로 저장). 커버 영상의 SponsorBlock 인트로·아웃트로 정보가 있으면 원곡과의 시간 차이를 자동으로 맞춥니다. 뮤직비디오를 틀 때는 인트로 길이(SponsorBlock 구간 또는 노래·영상 길이 차이)로 **자동 싱크**하고, 그래도 어긋나면 **− 싱크 +** 버튼으로 0.5초씩 조절합니다(곡별로 저장되어 다시 들어와도 유지). 동영상에 저절로 나오는 YouTube 자막은 항상 숨깁니다. |
| 기타 | 다음 곡으로 재생·현재 재생목록에 추가, 키보드 단축키(Space 재생, N/P 다음·이전, J/L 탐색, S 셔플, R 반복, M 음소거, F 플레이어 페이지), 미디어 키·잠금화면 컨트롤, 새로고침 후 대기열 복원, 모바일 레이아웃 |

## 구조

```
shared/   서버·클라이언트 공용 타입과 링크 파서
server/   API (Hono) — app.ts(라우트: 재생목록·앨범·검색·가사·다음 트랙·Spotify 곡 매칭), youtube.ts(youtubei.js), spotify.ts·soundcloud.ts(다른 서비스 목록·검색), normalize.ts(응답 정규화), mock.ts(목 데이터), node.ts(Node 실행)
worker/   Cloudflare Worker 진입점
src/      React 프론트엔드 (Vite)
```

## 로컬 실행

```bash
npm install
npm run dev        # 웹 http://localhost:5173 + API http://localhost:3001
npm run dev:mock   # YouTube 접속 없이 목 데이터로 UI 확인
```

자체 서버 하나로 띄우려면 `npm run build && npm start`를 실행하세요. `http://localhost:3001`에서 웹과 API를 함께 제공합니다.

환경 변수: `PORT`(기본 3001), `YT_LANG`(기본 `ko`), `YT_LOCATION`(기본 `KR`)

## 배포 (Cloudflare Workers)

`main` 브랜치에 푸시하면 `.github/workflows/deploy.yml`이 다음을 실행합니다.

1. 웹 앱을 빌드하고, **웹 앱 + API를 Cloudflare Worker 하나(`openmusic`)로 배포** → `https://openmusic.<계정 서브도메인>.workers.dev`
   - `/api/*`는 Worker가 처리하고, 나머지 경로는 빌드된 정적 파일(SPA)을 제공합니다.
2. 같은 웹 앱을 GitHub Pages에도 배포합니다(API는 1번 Worker 사용) → `https://<사용자>.github.io/<저장소>/`

처음 한 번 설정:

1. Cloudflare에서 **"Edit Cloudflare Workers"** 템플릿으로 API 토큰을 만들고, Workers & Pages 화면에서 **Account ID**와 workers.dev 서브도메인을 확인합니다.
2. GitHub 저장소 **Settings → Secrets and variables → Actions**에 `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`를 추가합니다.
3. (GitHub Pages도 쓰려면) **Settings → Pages → Source**를 **GitHub Actions**로 설정합니다.

로컬에서 Worker로 확인: `npm run worker:dev` (빌드 후 `wrangler dev`)

### 사용자 도메인 연결 (GitHub Pages, 예: `openmusic.kro.kr`)

1. 도메인 DNS에 **CNAME** 레코드를 추가합니다: `openmusic.kro.kr` → `<사용자>.github.io`
2. 저장소 **Settings → Pages → Custom domain**에 도메인을 입력하고 저장한 뒤, DNS 확인이 끝나면 **Enforce HTTPS**를 켭니다.
3. **Actions → Deploy → Run workflow**로 다시 배포합니다. 빌드 경로(`/OpenMusic/` ↔ `/`)는 Pages 설정에서 자동으로 감지됩니다.

등록한 재생목록은 브라우저에 주소(도메인)별로 저장되므로, 주소를 바꾸면 새 주소에서 다시 등록해야 합니다.

## 참고 / 제한

- 소유자가 외부 사이트 재생을 막은 곡(오류 101/150)은 재생할 수 없어 자동으로 건너뜁니다.
- 노래가 아닌 구간 건너뛰기는 SponsorBlock에 사용자가 구간을 등록해 둔 영상에서만 동작합니다. 크로스페이드는 다음 곡을 미리 틀어야 하므로, 자동재생이 막힌 일부 모바일 브라우저에서는 일반 넘김처럼 동작할 수 있습니다.
- 모바일 백그라운드 재생: 화면이 꺼지거나 다른 앱으로 가면 브라우저가 YouTube 플레이어를 멈추는데, 사용자가 멈춘 게 아니면 자동으로 다시 재생을 시도합니다. 브라우저 정책상 항상 되지는 않으며(특히 iOS), 그럴 때는 잠금 화면·알림의 재생 버튼으로 이어서 들을 수 있습니다.
- 큰 재생목록은 100곡씩 나눠 불러옵니다. 서버(Cloudflare 무료 요금제)의 요청당 CPU 제한 때문에 중간에 실패하면 자동으로 다시 시도하고, 그래도 안 되면 **나머지 곡 불러오기** 버튼으로 이어서 받을 수 있습니다.
- 브라우저 자동재생 정책 때문에 `/watch` 링크로 처음 들어오면 재생 버튼을 한 번 눌러야 합니다.
- YouTube 내부 API(InnerTube)는 예고 없이 바뀔 수 있습니다. 정보가 안 나오면 `youtubei.js`를 업데이트해 보세요.
- Cloudflare 무료 플랜은 요청당 CPU 시간이 짧습니다. 매우 큰 재생목록에서 오류가 나면 Workers 유료 플랜이나 Node 서버(`npm start`)로 배포하는 방법을 검토하세요.
- SoundCloud는 새 API 키 발급이 막혀 있어 soundcloud.com 웹 앱이 쓰는 공개 `client_id`를 찾아 씁니다(바뀌면 자동으로 다시 찾음). Spotify는 공식 API 없이 임베드 페이지를 읽습니다. 두 방식 모두 비공식이라 예고 없이 막힐 수 있습니다.
- 개인 학습·비상업 용도로 만든 프로젝트입니다. YouTube 서비스 약관을 지켜서 사용하세요.
